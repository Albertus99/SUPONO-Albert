# SUPONO

A top-down "eat your way up the food chain" game. You play a cube animal that grows by eating
smaller animals and food. Bigger animals hunt you, and each level is won by eating its goal animal
(up to the elephant). Built with Unity 6 (URP).

**Open:** `Assets/Content/Game/Scenes/MainMenu.unity` → Play.
**Test shortcuts:** `Tools ▸ Supono ▸ Progress` (add coins, unlock levels, reset or reveal the save).

## Tools & architecture

| Area | Used |
|---|---|
| Engine | Unity 6000.3, URP 17, new Input System, TextMesh Pro |
| DI / async | **VContainer** (project scope → main-menu / level child scopes), **UniTask** (every async flow takes a `CancellationToken`) |
| IAP | **Unity IAP 5.4** (`StoreController`), Fake Store (sandbox) in the editor |
| Analytics | **Firebase Analytics** SDK (13.x), console fallback |
| Art / audio | Kenney cube-pets, mini-forest, fantasy-town, survival and food kits; Hyper Casual UI pack; Baloo 2 font; custom toon shaders |

**Assemblies** (dependencies point downward only):

```
Supono.Editor     editor-only tools (Progress menu, Firebase define switch)
Supono.Debugging  optional debug module (installer, toggles, rule overrides, debug window)
Supono.App        game flow: scopes, menus, levels, progress, saves, shop, analytics, windows
Supono.UI         window manager, Window / ChoiceWindow, catalogs
Supono.Gameplay   animals, AI, food, camera, audio
```

Nothing in Gameplay, UI or App references `Supono.Debugging` (it is not auto-referenced).

**Folders:** scripts live in `Assets/Scripts`; everything else (data, prefabs, scenes, shaders,
audio) lives in `Assets/Content`.

## Key design decisions

- **Composition over flags.**
  - The player and NPCs share one body (`Animal` + `AnimalMotor` + `Eater` + `Stamina`).
  - Behaviour comes from a pluggable brain (`PlayerInputBrain` / `AiBrain`, both `IAnimalBrain`).
  - Roles are components (`PlayerAvatar`, `LevelGoal`).
  - AI moods are `AiBehaviourAsset` ScriptableObjects producing polymorphic intents (`Chase`, `Flee`, `MoveTo`…).
  - Diets are `FoodGroup` / `Diet` assets.
  - No `isPlayer`-style bools and no enums standing in for polymorphism.
- **The game doesn't depend on debug.** The game exposes extension points with normal-game defaults:
  - `IGameplayModifiers`
  - `ILevelAccess`
  - `ICharacterPricing`
  - `IDailyRewardSchedule`
  - `IIapStore`
  - `IMainMenuExtension`
  - `IWindowSource`

  `DebugInstaller` (a `ProjectInstaller` asset) re-registers these with decorators that wrap the defaults. With every toggle off they behave exactly like the defaults. Remove the asset from the project scope and no debug code runs.
- **One save point.**
  - `ISaveService` stores named sections in a single `save.json` in `persistentDataPath`.
  - Writes are atomic (temp file + replace) and keep a `.bak` copy as a fallback.
  - Every change is written immediately, so coins survive losing, quitting or crashing.
- **Data-driven content as assets.**
  - Tuning lives in ScriptableObjects: animal definitions, diets, AI behaviours, level, character and coin-pack catalogs.
  - Every window and popup is a prefab in `Prefabs/UI`, and the 5 levels and the menu are regular scenes. All of it was first generated by editor tooling during development, then kept as plain, hand-editable assets.
  - At runtime the game only instantiates prefabs; lists clone template children inside each prefab.
- **Window manager.**
  - Windows are prefabs with a layer (Hud / Screen / Popup / Overlay).
  - Flows `await` a window's choice.
  - Event subscriptions happen in the open callback, so input during the fade-in isn't lost.
- **IAP.**
  - `UnityIapStore` grants coins *before* confirming an order, so an interrupted purchase is re-delivered and granted on the next launch.
  - The UI awaits a `PurchaseResult` and shows a success or failure popup.
- **Analytics.**
  - Each event is a class (`LevelStartEvent`, `PurchaseClickEvent`, …) that describes its own parameters.
  - Backends (`FirebaseAnalytics`, `ConsoleAnalytics`) never switch over event types.
  - The editor script `FirebaseDefine` turns on `SUPONO_FIREBASE` when the SDK is present.
  - Without `google-services.json`, Firebase falls back to the console, so no backend setup is required.
- **Rendering.**
  - Toon look: a cel-shading shader plus a full-screen ink outline.
  - The outline scales with the camera's focus distance: creases fade and silhouettes thin far away, and a grazing-angle correction stops false lines on the ground.
- **Character previews.**
  - A preview-stage prefab renders every character into one atlas texture, with one camera for the whole grid.
  - Each card shows its tile; drag sideways to spin (with momentum), drag up or down to scroll.

## Feature checklist

- [x] Core loop: eat smaller animals and food to grow; get eaten by bigger ones; eat the goal animal to win
- [x] Player and NPCs share a controller (CharacterController + new Input System); passive / neutral / aggressive AI that reacts to relative size
- [x] Common-sense animal scales (bee < cat < dog < … < elephant)
- [x] Stamina and sprint; stamina refills only from energy food
- [x] 5 designed levels with obstacles and progression (each win unlocks the next)
- [x] Currency from map pickups, animal bounties, level rewards and daily rewards; banked immediately, even on a loss
- [x] Main menu, level intro, HUD, pause, result, loading and level select (window manager)
- [x] **Character Selection**: scrollable grid of 10 characters with live, drag-to-spin 3D previews; unlock with coins, stats come from the model
- [x] **Shop & IAP simulation**: three coin packs through Unity IAP (Fake Store in the editor); busy state, success popup (+coins, counter animation) and failure popup (reason)
- [x] **Daily Rewards**: once-per-day popup on a 7-day ladder; coin-flight feedback; the streak resets if a day is missed
- [x] **Debug Menu** from the main menu (gear): god mode, infinite stamina, coin rush, unlock levels, free characters, no cinematics, daily reward every visit, fail purchases, outlines off, mute. Every toggle is independent; all off (or Reset All) = default game
- [x] **Firebase Analytics**: `level_start`, `level_end`, `purchase_click`, `purchase_success` / `purchase_failed`, `daily_reward_claim`, `character_unlock`, `select_item` (see `Assets/Scripts/App/Analytics`)
- [x] Saves: a single save service; progress, coins, characters, streak and debug toggles persist
- [x] Toon shading and outline, cinematic zoom-ins and slow motion on big bites, a close-up when you're eaten
- [x] Audio: sound effects, each animal's own voice when eaten, looping background music
- [x] TextMesh Pro for all UI text

### Example: logging an event

```csharp
// LevelFlow, when play begins
analytics.Log(new LevelStartEvent(LevelNumber, LevelName, progress.SelectedCharacterId));

// An event describes itself; any backend can send it
public sealed class LevelStartEvent : AnalyticsEvent
{
    public override string Name => "level_start";
    public override void Describe(IEventParameters p)
    {
        p.Add("level_name", levelName);
        p.Add("level_number", levelNumber);
        p.Add("character", character);
    }
}
```
